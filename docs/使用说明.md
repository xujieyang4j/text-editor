# Lumen Editor 安装与使用说明

> 日常编辑、搜索、预览、布局、Git 和项目工具的图文操作说明，请参阅
> [《Lumen Editor 编辑器使用指南》](./编辑器使用指南.md)。本文主要说明安装、源码运行与打包。

Lumen Editor 是一款基于 **Electron + TypeScript + CodeMirror 6** 的跨平台桌面文本编辑器，
可在 **Windows、macOS、Linux** 上运行。

本文档面向两类读者：
- **普通用户** —— 直接使用打包好的安装包（见「一、安装（普通用户）」）
- **开发者** —— 从源码运行或自行打包（见「二、从源码运行（开发者）」）

---

## 一、安装（普通用户）

从发布页下载对应平台的安装包后按下表操作。安装包由 `npm run dist:*` 生成，产物位于
项目的 `release/<版本号>/` 目录。

| 平台 | 文件 | 安装方式 |
| --- | --- | --- |
| **Windows** | `Lumen Editor-<版本>-win-x64.exe`（NSIS 安装程序） | 双击运行，可自选安装目录 |
| **Windows** | `...-win-x64.exe`（portable 便携版） | 免安装，双击即用 |
| **macOS** | `Lumen Editor-<版本>-mac-<arch>.dmg` | 打开后把图标拖进「应用程序」 |
| **Linux** | `Lumen Editor-<版本>-linux-x86_64.AppImage` | `chmod +x *.AppImage` 后双击/命令行运行 |
| **Linux** | `...-linux-amd64.deb` | `sudo dpkg -i *.deb`（Debian/Ubuntu 系） |

### 平台提示

- **macOS 首次打开**：若提示「无法验证开发者」，在「系统设置 → 隐私与安全性」点击「仍要打开」，
  或运行 `xattr -dr com.apple.quarantine "/Applications/Lumen Editor.app"`。
  （应用未做代码签名，属正常现象。）
- **Windows SmartScreen**：若弹出「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
- **Linux AppImage** 需要 FUSE。若报错，可 `./Lumen*.AppImage --appimage-extract` 后运行
  解出的 `AppRun`，或安装 `libfuse2`。

## 二、从源码运行（开发者）

### 环境要求

- **Node.js** ≥ 18（推荐 20/22）与 npm
- 首次安装需联网下载 Electron 运行时二进制
- **图形桌面环境**（运行 GUI 必需；纯服务器/无显示器环境见下文 FAQ）

### 步骤

```bash
# 0. 获取代码（GitHub）
git clone git@github.com:xujieyang4j/text-editor.git
cd text-editor

# 1. 安装依赖（含 Electron 二进制）
npm install

# 2. 开发模式启动（热重载）
npm run dev
```

> 已有一份被 `npm audit fix --force` 破坏的旧目录时，**不要在里面修**——换个干净目录重新
> `git clone`，避免残留的错误依赖树继续干扰。

若你所在网络下载 Electron 二进制很慢或超时，先设置国内镜像再安装：

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/   # Windows: set ELECTRON_MIRROR=...
npm install
```

若 macOS 将开发环境的 `Electron.app` 误报为恶意软件/已损坏或移到废纸篓，使用项目内置命令：

```bash
npm run dev:mac
```

该命令会自动恢复缺失的 Electron.app、仅清除当前项目运行时的隔离属性、执行临时签名并验证，
然后直接启动编辑器；不会关闭 Gatekeeper 或修改系统级安全设置。若只修复不启动，可执行
`npm run fix:mac`。正式发布的 macOS 安装包仍应使用 Developer ID 签名和 Apple 公证。

### 无需 GUI 的校验命令

在服务器/CI 上无法开窗口时，仍可校验代码正确性：

```bash
npm run typecheck   # TypeScript 类型检查（main 与 renderer 两套配置）
npm run build       # 打包 main / preload / renderer 到 out/
```

## 三、界面与基本使用

启动后界面分为三个区域：

```
┌───────────┬─────────────────────────────────┐
│  侧边栏    │  标签栏                          │
│ (文件树)   ├─────────────────────────────────┤
│           │                                  │
│           │        编辑区 (CodeMirror)        │
│           │                                  │
│           ├─────────────────────────────────┤
│           │  状态栏：行列 / 语言 / 编码 / 换行  │
└───────────┴─────────────────────────────────┘
```

- **新建文件**：`Ctrl/Cmd+N`，或菜单 File → New File。
- **打开文件**：`Ctrl/Cmd+O` 选择单个文件；文件会以新标签打开。
- **最近文件**：File → Open Recent File… 可重新打开此前通过编辑器打开过的文件；路径须仍在最近列表中，
  打开时会重新进行受限授权。
- **打开文件夹**：`Ctrl/Cmd+Shift+O` 载入工作区；侧边栏默认收起，按 `Ctrl/Cmd+B` 展开后，
  点击文件夹展开、点击文件打开。
- **拖放打开**：可把操作系统中的文件或文件夹直接拖到编辑器窗口。文件会作为标签打开；第一个文件夹
  成为主工作区，额外文件夹加入多根项目。拖放路径只在 preload 中提取，主进程会逐项验证、授权和读取；
  不支持网页链接、文本或非本地文件的拖放。
- **保存**：`Ctrl/Cmd+S`。未命名文件会弹出保存对话框；`Ctrl/Cmd+Shift+S` 为另存为。
- **编码与换行符**：状态栏中的编码和换行符均可点击。编码可选 `UTF-8`、`UTF-8 BOM`、
  `UTF-16 LE`、`UTF-16 BE`，换行符可选 `LF`、`CRLF`、`CR`。选择只设置下次保存的
  目标格式并标记为未保存；保存、全部保存（`Ctrl/Cmd+Alt+S`）或自动保存时才会写入磁盘。
  混合换行的文件在保存时会统一为所选换行符。
- **打开文件的编码识别**：编辑器基于 BOM 区分四种 Unicode 格式：UTF-8 BOM 对应
  `UTF-8 BOM`，UTF-16 BOM 对应 `UTF-16 LE` 或 `UTF-16 BE`；没有 BOM 时按 `UTF-8`
  读取，不会根据内容猜测旧式编码或其他编码。
- **多标签**：顶部标签栏切换；标题前的 `●` 表示有未保存改动；点标签上的 `×` 关闭。
  关闭有改动的标签会弹确认框，避免误丢内容。
  按住 `Ctrl/Cmd` 点击多个标签可多选，再通过 View → Split Selected Tabs into Groups 并排打开，
  用于快速比较多个文件。可直接在同一分栏的标签栏中拖动标签重排；多选的标签会作为一组一起移动。
- **命令面板**：`Ctrl/Cmd+Shift+P` 打开，模糊搜索并执行任意命令（Sublime 风格）。
- **Goto Anything**：`Ctrl/Cmd+P` 模糊查找工作区文件；输入 `:` 后接行号或 `行:列` 跳转到当前文件位置，输入 `@`
  后接名称跳转到当前文件的符号（函数/类/标题等），输入 `#` 搜索项目符号；也可输入
  `文件名:行号[:列号]`，例如 `main.ts:120:8`，直接打开匹配文件并精确定位。
- **跳转到符号**：`Ctrl/Cmd+R`；**跳转到行**：`Ctrl/Cmd+G`（也支持 `行:列`、`+/-相对行`、`百分比%`）；**跳转到匹配括号**：`Ctrl/Cmd+Shift+\`。
  光标放在或紧邻 `()`、`[]`、`{}` 等括号时即可在两端跳转；没有匹配时不会移动。
- **查找/替换**：`Ctrl/Cmd+F` 打开当前文件查找面板，`Ctrl/Cmd+H` 查找并替换。`F3` /
  `Shift+F3` 分别跳到当前文件中的下一个 / 上一个匹配，“编辑”菜单与命令面板也提供相同命令；它们不同于
  工作区 Find Results 使用的 `F4` / `Shift+F4`。
- **在文件中查找/替换**：`Ctrl/Cmd+Shift+F` / `Ctrl/Cmd+Shift+H` 打开工作区面板；支持正则、
  区分大小写、全词，以及 `**/*.ts` 等包含/排除 glob。批量替换前会再次确认，并保留文件原编码与换行符。
  多根项目会在所有已加入的根目录中搜索和替换，结果仍受全局上限约束。
  已执行过的搜索词与替换词会作为输入建议保留（最多 50 条）。
- **Find Results 结果页**：执行工作区查找后，匹配会保留为独立结果视图；`F4` / `Shift+F4` 可在匹配间
  前后跳转，点击任意结果直接打开对应文件与列。
- **多组布局与窗口**：View 菜单可切换单组、2/3 列、4 宫格；每组拥有独立标签栏和活动文件。
  可将当前文件移动或克隆至下一组，并用 `Ctrl/Cmd+Alt+[` / `]` 切换焦点组。
  File → New Window 新建独立窗口；每个窗口都有独立的稳定会话、布局、组内标签顺序和活动文件，
  再次启动时会分别恢复，未保存内容也会随各自窗口保存。
- **多根项目与最近项目**：Project → Add Folder to Project… 可把额外目录加入当前工作区；文件树与
  Goto Anything 会同时显示所有根目录。Project → Open Recent Project… 可重新打开最近使用过、且仍存在的
  项目目录。构建、Git 与项目配置仍以第一个（主）根目录为准，避免跨仓库误操作。
  Project → Remove Folder from Project… 可移除任一根目录；已打开的标签仍保留，且只保留这些文件的
  直接访问权限，不再把已移除目录作为可搜索、可浏览或可运行命令的工作区。
  Project → Import Sublime Project… 可导入 `.sublime-project` 中存在的 folders、排除规则和 Build
  Systems/Variants；导入前会列出根目录并要求确认，不会执行 Sublime 的 Python 插件或加载其 workspace。
- **项目符号与统一导航历史**：`Ctrl/Cmd+Shift+R` 在整个工作区查找已索引的函数、类与 Markdown 标题。
  `Alt+←` / `Alt+→` 可在跳转到行、Goto Anything（文件、行、当前文件符号、项目符号）、大纲、
  工作区搜索结果、构建问题、定义/引用、书签、匹配括号和改动跳转之间后退/前进。只有成功且确实移动
  到新位置后才会记录；取消、失败或原地跳转不会污染历史。仍打开的未命名文档可返回原分屏组，关闭的
  文件在路径仍可用时可按路径重开；这份历史只在本次运行中保留，重启后不会恢复。
- **代码大纲**：View → Toggle Outline 会在侧边栏显示当前文件的函数、类和 Markdown 标题；可筛选并
  点击跳转，光标所在符号会高亮。它复用本地符号提取，不启动语言服务，也不会读取工作区以外的文件。
- **分屏与标签状态**：View → Toggle Split Editor（`Ctrl/Cmd+Alt+2`）打开第二个同步 CodeMirror 编辑器；
  每个标签会保留自己的撤销历史、选区、折叠和光标状态。
- **书签 / 宏 / 片段**：`Ctrl/Cmd+F2` 切换书签，`F2` / `Shift+F2` 跳转；Tools 菜单可录制并重放
  常用行操作宏，或通过 Insert Snippet… 插入内置/插件片段。
- **文件树操作**：右键文件/目录可新建、重命名、移到系统回收站、在文件管理器显示；外部修改的干净文件
  还可通过 Move To… 选择目标目录进行移动；目标目录由系统对话框显式选择，若重名则不会覆盖。
  会自动刷新。若磁盘文件变化时本地仍有未保存编辑，顶部会提供**比较、重新加载磁盘版本、保留本地版本、
  另存为**四种冲突处理方式，绝不静默覆盖本地编辑。刷新文件树会保留已展开的目录。
  文件树或标签页右键可复制完整路径或项目相对路径；File 菜单和命令面板也提供同样操作。
- **构建与语言工具**：Tools → Build 打开构建输出；Tools → Format Document 可使用项目配置的 LSP
  或 stdin/stdout 格式化工具，并将诊断显示在编辑器 gutter。LSP 会按工作区/语言保持常驻并在
  编辑防抖后发送 `didChange`；Tools → Select Build System… 可选命名构建和 Variant，含文件/行/列的
  输出会变为可点击 Problems。外部命令在每个应用会话首次运行前均须确认。
- **语言服务器状态与日志**：Tools → Show Language Servers（命令面板：`LSP: Show Language Servers`）
  按服务器显示正在启动、运行中、正在停止、已停止或错误状态、工作区、PID 与能力；选择服务器可查看
  有界的 stderr/服务器通知日志并重启。日志不包含原始协议消息；畸形或超限协议帧会终止异常服务。
  打开面板本身不会运行命令，实际启动外部语言服务器时仍须按本应用会话首次确认。
- **项目终端**：Tools → Toggle Terminal（`Ctrl/Cmd+Alt+T`）可在当前主项目根目录启动一个交互式
  shell。首次启动会明确显示工作目录与风险并要求确认；终端输出和输入只经受控 IPC 转发，网页或插件
  无法获得 Node、文件系统或进程对象。停止、关闭窗口或退出应用会终止该 shell 及其 POSIX 子进程组。
  当前终端采用 `TERM=dumb` 的基础文本交互，适合运行命令、脚本和测试；全屏/光标控制类 TUI（例如 vim、
  htop）不属于支持范围。
- **文档统计**：Tools → Document Statistics 显示当前缓冲区的行数、字符数、非空白字符数与词/标记数；
  若存在选区，还会单独显示选区统计。该功能只读取内存中的当前内容，不需要保存或打开项目，也不会修改文本。
  统计按 Unicode 字素和词段处理，可正确覆盖中文连续文本、组合字符与 emoji。
- **语言导航**：配置 LSP 后，命令面板可执行 Hover、Go to Definition、Find References 与 Rename Symbol；
  补全会在输入时异步请求。响应会按当前文件版本与光标位置校验，过期响应不会覆盖刚切换的标签或新编辑。
- **行操作**：`Alt+↑/↓` 移动行、`Shift+Alt+↑/↓` 复制行、`Ctrl/Cmd+Shift+K` 删除行、
  `Ctrl/Cmd+Shift+D` 复制行/选区、Win/Linux `Ctrl+Backspace` / `Delete`（macOS `Alt+Backspace` / `Delete`）删除前/后一个单词、`Ctrl/Cmd+Shift+Backspace` / `Delete` 删除至行首/行尾、`Ctrl/Cmd+Shift+Enter` / `Enter` 在上方/下方新建自动缩进空行、`Ctrl+T` 转置光标两侧的相邻字符、`Ctrl/Cmd+/` 切换注释，
  “编辑”菜单和命令面板还提供“升序排列行”“降序排列行”“反转行顺序”“删除重复行”“删除空白行”。
  每个非空选区都会扩展到其触及的完整物理行，不相邻的行块分别处理；所有选区均为空时处理全文，选区和
  光标会随编辑映射到对应位置。五项操作都会保留剩余内容原有的末尾换行状态；“删除空白行”仅删除内容
  长度为零或只含空格、Tab 的物理行，若删掉所有行则结果为空。“删除重复行”按整行内容精确匹配，并按
  原顺序稳定保留第一次出现。转置在行首或没有可交换字符时
  不会修改文本，并可正常撤销。
- **文本转换与片段**：命令面板可转换缩进、保存用换行符、大小写、合并行、拆分选择为多行、
  清理行尾空白。插入 `${1:名称}` / `${2}` / `${0}` 形式的 snippet 后，可用 `Tab` / `Shift+Tab`
  在占位符之间跳转；同编号占位符会镜像同步。插件 snippet 可声明 `trigger` 与 `scope`，在匹配语言中
  输入 trigger 后按 `Tab` 直接展开。录制的宏会保存为项目内 `.lumen-macros.json` 的有序编辑/命令流，
  之后从命令面板重放；旧版快照型宏仍兼容。
  大小写转换会分别作用于全部非空多选区；若没有选区，则转换全文，并保留转换后的选区范围。
  合并行会分别处理多个选区覆盖的行块；没有选区时合并当前行和下一行，并清理换行两侧的多余空白。
  最后一行等无可合并位置不会改动文本，会在状态栏提示。
  「Reindent Selection」（`Ctrl/Cmd+Alt+\`）会按当前语言的本地语法规则重新计算选中行的缩进，
  不启动 LSP、终端或外部格式化命令；无法推断缩进时不改动文本并显示提示。
- **多光标与选区**：除 `Alt` 点击/拖动和矩形选择外，Selection 菜单提供「Add Next Occurrence」、
  「Select All Occurrences」及在上下行添加光标；`Shift+Alt+→` / `←` 可逐级扩展/缩小选区——
  代码优先按语法结构扩展，纯文本回退为单词、当前行、全文；Edit → Toggle Block Comment 支持块注释。
  「Select Line」（Windows/Linux：`Alt+L`；macOS：`Ctrl+L`）会选择整行；「Select to Matching Bracket」
  会把选区活动端延伸到 `()`、`[]`、`{}` 的另一端，无匹配时保持原选区。
  「Select Enclosing Syntax」（`Ctrl/Cmd+I`）会基于当前语言语法树选中下一层外部结构，例如表达式、
  参数、调用或代码块；纯文本、未解析语法或达到最大结构时保持原选区并提示。
  「Split Selection into Lines」会将全部非空选区覆盖的每行变成行首光标，重叠行会去重；选区刚好结束在
  下一行开头时不会多生成光标。没有选区时不改变光标，并会显示提示。
- **代码折叠**：除左侧 gutter 图标外，View 菜单和命令面板提供 Fold/Unfold Current 与 Fold/Unfold All。
  当前块在 Windows/Linux 使用 `Ctrl+Shift+[` / `]`，macOS 使用 `Cmd+Alt+[` / `]`；全部折叠/展开使用
  `Ctrl+Alt+[` / `]`。没有可用折叠项时不会改变内容，并会显示状态提示。
- **增量 Diff**：保存文件后，继续编辑会在行号左侧显示新增（绿）、修改（蓝）和删除（橙）的标记。
  Goto → Next/Previous Change 可循环跳转，Edit → Revert Current Change 可在确认后撤销当前 hunk；
  比对基线是最近保存/磁盘版本，避免无确认地改写 Git HEAD。
- **语法高亮**：默认按文件扩展名自动识别（100+ 语言）。要**手动指定**：点状态栏右下角的语言
  名，或命令面板执行「View: Set Syntax…」，在弹出列表里选择——手动选择后不再被自动识别覆盖。
- **JSON 工具与视图**：打开 `.json` / `.jsonc` / `.geojson` / `.har`，或将语法设为 JSON 后，编辑区右上角
  会出现**格式化、压缩、视图**工具。格式化与压缩仅在 JSON 可解析时改写源码；JSON 视图会在右侧统计
  key、对象、数组、基础值和最大深度，并提供点击基础值编辑、添加/删除对象键及数组项等操作。所有树编辑
  都会同步为格式化的 JSON 源码，正常参与撤销、自动保存和热退出；解析失败时保留源码并在视图显示错误。
- **Minimap / 缩进参考线 / 标尺**：Minimap 可用「View: Toggle Minimap」开关；缩进参考线、
  竖直标尺、行尾空白高亮由设置文件控制（见下文「设置」）。
- **Markdown 预览**：Markdown 文件按 `Ctrl/Cmd+Shift+V`（或点右上角**悬浮预览图标**、或
  「View: Toggle Markdown Preview」）在旁边打开渲染预览，随输入实时更新。判定为 Markdown 的条件：
  文件名以 `.md` 等结尾，**或**在状态栏把语法设为 Markdown（未保存文件也能预览）；渲染 HTML 经
  DOMPurify 消毒，内嵌脚本不会执行。
- **HTML 在浏览器打开**：打开 `.html` 文件时，编辑器右上角出现**悬浮浏览器图标**，点击它（或
  「View: Open in Browser」）用系统浏览器预览。已保存且未改动的文件直接打开原路径；未保存或未命名
  内容使用临时快照，不弹保存窗口、不修改源文件；脏文件的相对资源路径仍以原文件目录为基准。
- **字号缩放**：`Ctrl/Cmd+=` 放大、`Ctrl/Cmd+-` 缩小、`Ctrl/Cmd+0` 复位。
- **热退出 / 会话恢复**：即使意外退出或机器崩溃，再次打开也会自动重开上次的标签与工作区文件夹，
  并**保留未保存的编辑**（有改动的文件恢复为脏状态带 `●`，未命名草稿也保留）；边打字边防抖写盘，
  临时文件加原子替换可避免未完成写入覆盖上一份完整快照。每个分栏还会恢复多光标选区与横/纵滚动位置；`Ctrl/Cmd+Shift+T` 重新打开刚关闭的标签。
- **主题/换行/侧栏**：`Ctrl/Cmd+K` 切换明暗主题，`Alt+Z` 切换软换行，`Ctrl/Cmd+B` 显隐侧边栏。
- **图形化设置**：Preferences → Open Settings…（`Ctrl/Cmd+,`）可即时修改语言、配色、字号、缩进、
  自动保存、编辑器辅助功能与文件大小上限；设置自动写入 userData 中的 `settings.json`，下次启动继续生效。
- **专注模式**：View → Distraction Free Mode（`Shift+F11`）隐藏侧栏、标签与状态栏并居中编辑列；
  按 `Esc` 恢复。该模式只调整界面，不会改变文件、工作区或窗口全屏状态。
- **配色方案、Git 与市场**：View → Select Color Scheme… 可单独选择 Dark、Light、Solarized Dark 或
  Dracula 的 UI/编辑器配色；View → Toggle Git Changes 可查看 diff，并在明确确认后暂存、取消暂存、
  丢弃工作区改动、提交、创建/切换分支。检测到冲突时可从面板打开冲突文件；编辑器不会自动执行 Git
  写操作。双击文件后可在 Git 面板选择 hunk，并在确认后仅暂存或丢弃该 hunk；History 和 Blame 为只读
  查看。Tools → Browse Plugin Marketplace… 从项目配置的 HTTPS 源读取插件清单，安装前会显示来源并确认。
- **更新检查**：Help → Check for Updates 会查询官方 GitHub Release，发现新版本后只打开对应发布页；
  不会在后台下载、替换应用或绕过系统的安装/签名提示。

### 设置（持久化）

设置以 JSON 保存在系统的 userData 目录，改动即时写入、下次启动沿用：

- **Windows**：`%APPDATA%\Lumen Editor\settings.json`
- **macOS**：`~/Library/Application Support/Lumen Editor/settings.json`
- **Linux**：`~/.config/Lumen Editor/settings.json`

可配置项（同一目录下，旧窗口使用 `session.json`，多窗口使用 `session-<id>.json` 保存标签与文件夹，一般无需手动编辑）：

```jsonc
{
  "fontSize": 14,                    // 字号(px)，也可用 Ctrl/Cmd +/- 调整
  "tabSize": 4,                      // Tab 宽度
  "insertSpaces": true,             // 用空格代替制表符
  "theme": "dark",                  // "dark" | "light"
  "wordWrap": false,                // 软换行
  "spellCheck": false,              // 使用系统字典的拼写检查
  "autoSave": "off",             // "off" | "after_delay" | "on_focus_change"
  "autoSaveDelayMs": 1000,          // after_delay 模式的延时
  "distractionFree": false,         // 专注模式（Shift+F11）
  "showMinimap": true,              // 右侧缩略图
  "showOutline": false,             // 侧栏当前文件大纲
  "showIndentGuides": true,         // 缩进参考线
  "highlightTrailingWhitespace": true, // 行尾空白高亮
  "rulers": [80, 120]               // 竖直标尺所在列(留空数组则不显示)
}
```

Preferences → Import Sublime Settings… 可导入用户选择的 `.sublime-settings`（支持 `//` / `/* */`
注释和尾逗号），映射字体大小、缩进、软换行、标尺、行尾空白、配色和 `spell_check`。解析后会先询问
是否应用，确认后才写入 Lumen 设置；无法映射的 Sublime 项不会执行或被静默当作脚本。`spellCheck` 启用后
使用 Electron/Chromium 的原生拼写检查，适合 Markdown 与普通文本，具体字典由操作系统提供。
View → Toggle Spell Check 可直接开关；对源码语法默认不启用，避免干扰代码编辑。
File → Cycle Auto Save Mode 可依次切换关闭、延时保存和失焦保存；自动保存仅写入已有路径的文件，
未命名草稿仍只通过热退出会话保存，不会自动弹出系统保存对话框。
Preferences → Import Sublime Keymap… 会把 `.sublime-keymap` 中可安全映射的简单按键序列导入为项目
`keyBindingRules`；带参数的命令、复杂 context selector、未知命令及 Package 命令会显示为跳过，绝不执行。

### 项目配置、语言工具与插件

对打开的工作区执行 **Project → Configure Project…** 可以写入根目录 `.lumen-project.json`。
常用结构如下（未知或不合法字段会被安全忽略）：

```jsonc
{
  "exclude": ["**/generated/**", "**/*.min.js"],
  "buildCommand": "npm test",
  "maxFileSizeMB": 20,               // 在用户设置 settings.json 中配置；超出时不会加载到编辑器
  "keyBindings": { "Mod+Shift+R": "build" },
  "keyBindingRules": [
    { "keys": ["Mod+K", "Mod+C"], "command": "trim-trailing-whitespace", "when": "editor" }
  ],
  "marketplaceUrls": ["https://example.com/lumen-marketplace.json"],
  "plugins": ["team-snippets"],
  "languageTools": {
    "Python": { "command": "black -q -", "args": [] }
  },
  "languageServers": {
    "TypeScript": { "command": "typescript-language-server", "args": ["--stdio"] }
  },
  "buildSystems": [
    {
      "name": "Test",
      "command": "npm",
      "args": ["test"],
      "saveBeforeBuild": true,
      "fileRegex": "([^:\\n]+):(\\d+):(\\d+):\\s*(.*)",
      "variants": [
        { "name": "Watch", "args": ["test", "--", "--watch"] }
      ]
    }
  ]
}
```

Language tool 从标准输入接收当前文档：普通文本输出会当作格式化结果；也可输出
`{ "content": "...", "diagnostics": [...] }`。语言服务器遵循标准 LSP JSON-RPC，
Lumen 发送 `initialize`、`didOpen`、`didChange`、`textDocument/formatting`、补全、悬停、定义、
引用和重命名请求，并显示 `publishDiagnostics`。同一工作区/语言服务会保持运行，编辑防抖后会发送
`didChange` 并实时更新诊断。LSP 协议帧的头部和负载均有大小上限；畸形或超限帧会记录为协议
错误并终止对应服务，避免异常数据持续占用资源。面板日志只保留有界的 stderr 与服务器通知摘要，不记录
原始 JSON-RPC 消息。
`buildSystems` 支持命名构建、Variant、工作目录和保存前构建；`fileRegex` 的第 1–4 个捕获组应依次为
文件、行、列、消息，Problems 点击后会跳转到相应位置。
结构化 Build System 的 `command`、`args`、`workingDirectory` 与 `env` 可使用 `$project_path`、`$file`、
`$file_path`、`$file_name`、`$file_base_name`、`$file_extension` 变量；它们默认直接执行而非经 shell
拼接，避免含空格路径和转义造成歧义。手工输入的单行构建命令仍走 shell，并会保持明确的会话确认。
未配置 LSP 时，自动补全会先用已打开文件、再异步加载受限的项目词条索引；项目符号/定义导航会使用
同一索引回退，Find References 则执行全词工作区搜索。
Tools → Import Sublime Build System… 可把单个 `.sublime-build` 的 `cmd` / `shell_cmd`、工作目录、
环境变量与 Variants 转入当前项目；仅解析 JSON-with-comments，导入和实际运行均会分别确认。
Tools → Install Local Plugin… 可从本地目录安装声明式插件；插件目录必须含 `plugin.json`，仅能提供
命令面板 insert-text 命令和 snippets，不能执行 Node/系统代码。可选的 `extension.worker` 在受控
Web Worker 中运行：不能访问 Electron、Node、文件系统、网络或进程；它只能通过声明的
  `document-read` / `document-edit` 权限读取或替换当前文档，并且首次启用会请求确认。Worker 路径必须在
  插件目录内，源码上限为 512 KB。Marketplace 与 manifest URL 均只接受 HTTPS；若市场插件提供 Worker，
  必须与 manifest 同源、提供 `sha256-...` 完整性摘要，校验通过后才会落到插件目录并在受控 Worker 中运行。
Tools → Import Sublime Snippet… 可导入用户选择的单个 `.sublime-snippet`，转换其 `content`、`tabTrigger`
和 `scope` 为项目级声明式 snippet；导入前会确认，XML 中不执行任何脚本、Package Python 代码或命令。
`keyBindingRules` 支持单键或多键序列，且可用 `when` 限制在 `editor`、`find-results`、`git` 或 `build`
上下文。Git 面板的暂存、取消暂存、丢弃、提交、创建/切换分支均会显示确认，且命令固定在主项目根
执行，避免把跨项目路径交给 Git。

应用支持单实例运行、从文件关联/命令行打开常见文本文件；文件关联在重新打包安装后生效。

## 四、自行打包安装包（开发者）

产物输出到 `release/<版本号>/`：

```bash
npm run dist          # 为当前操作系统打包
npm run dist:win      # Windows：NSIS 安装程序 + 便携版
npm run dist:mac      # macOS：.dmg + .zip
npm run dist:linux    # Linux：AppImage + .deb
```

打包目标在 `electron-builder.yml` 中配置。注意：
- **macOS 安装包必须在 macOS 上构建**（苹果工具链限制）。
- Windows / Linux 目标在多数系统上可跨平台构建（在 Linux 上打 Windows 包可能需要 Wine）。

仓库的 GitHub Actions 会在 Ubuntu、Windows 与 macOS 上运行类型检查、构建、无界面 GUI smoke test
和文件索引基准；推送 `v*` tag 时会构建各平台产物并上传至 GitHub Release。发布签名与 Apple 公证
依赖仓库机密变量，未配置时对应步骤会跳过，不能把未签名产物视为正式发行版。

## 五、常见问题（FAQ）

**Q：⚠️ 千万不要跑 `npm audit fix --force`！**
`npm install` 后会提示若干安全漏洞并建议 `npm audit fix --force`——**请忽略这个建议**。
这些漏洞**全部位于构建/打包工具链**（`tar`、`esbuild`、`vite`、`electron-builder` 的依赖），
只在你本地 `build` / `dist` 时用到，**不会打包进最终应用、不影响终端用户、不影响运行时安全**，
属于可接受的低风险项。而 `--force` 会把 `electron`、`vite`、`electron-vite`、`electron-builder`
强制升级到互不兼容的大版本，导致：
- 再次 `npm install` 报 `ERESOLVE` peer 依赖冲突；
- `npm run dev` 报 `SyntaxError: ... does not provide an export named 'cac'`，工具链彻底崩溃。

本项目已在 `package.json` + `package-lock.json` 中**锁定精确版本**为一套经验证兼容的组合
（electron 31.7.7 / electron-vite 2.3.0 / vite 5.4.21 / electron-builder 24.13.3 / typescript 5.9.3）。

**若已经误跑了 `--force` 把环境弄坏，如何恢复？** 两种方式任选：
```bash
# 方式 A（推荐）：从 GitHub 重新 clone 干净代码
cd .. && git clone git@github.com:xujieyang4j/text-editor.git text-editor-clean
cd text-editor-clean && npm install

# 方式 B：在原目录强制装回锁定版本
rm -rf node_modules package-lock.json
git checkout package.json package-lock.json   # 恢复锁定的版本清单
npm install
```

**Q：`npm install` 报 `EROFS: read-only file system` / npm 缓存目录只读？**
默认缓存目录不可写时，指定一个可写目录：
```bash
npm install --cache /可写路径/.npm-cache
```

**Q：安装卡在下载 Electron，或报 `ETIMEDOUT`？**
设置镜像后重装（见上文「从源码运行」）：
```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm install
```

**Q：在无显示器的 Linux 服务器上 `npm run dev` 崩溃，报 `libgbm.so.1: cannot open shared object file` 或直接 core dump？**
Electron 需要图形库和显示服务，纯服务器环境默认不具备。两种解决办法：
1. 安装依赖库与虚拟显示后再跑：
   ```bash
   sudo apt-get install -y libgbm1 libwayland-server0 xvfb   # Debian/Ubuntu
   xvfb-run -a npm run dev
   ```
2. 直接在带桌面的机器（个人电脑/带 GUI 的虚拟机）上运行。
> 普通用户在正常的 Windows / macOS / Linux 桌面系统上无需任何额外配置。

**Q：只想验证代码没问题，但机器开不了窗口？**
运行 `npm run typecheck` 和 `npm run build` 即可，二者都不需要图形界面。
