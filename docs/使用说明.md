# Lumen Editor 安装与使用说明

Lumen Editor 是一款基于 **Electron + TypeScript + CodeMirror 6** 的跨平台桌面文本编辑器，
可在 **Windows、macOS、Linux** 上运行。

本文档面向两类读者：
- **普通用户** —— 直接使用打包好的安装包（见「一、安装（普通用户）」）
- **开发者** —— 从源码运行或自行打包（见「二、从源码运行（开发者）」）

---

## 一、安装（普通用户）

从发布页下载对应平台的安装包后按下表操作。安装包由 `npm run dist:*` 生成，产物位于
项目的 `release/<版本号>/` 目录。

| 平台 | 文件 | 安装方式 |
| --- | --- | --- |
| **Windows** | `Lumen Editor-<版本>-win-x64.exe`（NSIS 安装程序） | 双击运行，可自选安装目录 |
| **Windows** | `...-win-x64.exe`（portable 便携版） | 免安装，双击即用 |
| **macOS** | `Lumen Editor-<版本>-mac-<arch>.dmg` | 打开后把图标拖进「应用程序」 |
| **Linux** | `Lumen Editor-<版本>-linux-x86_64.AppImage` | `chmod +x *.AppImage` 后双击/命令行运行 |
| **Linux** | `...-linux-amd64.deb` | `sudo dpkg -i *.deb`（Debian/Ubuntu 系） |

### 平台提示

- **macOS 首次打开**：若提示「无法验证开发者」，在「系统设置 → 隐私与安全性」点击「仍要打开」，
  或运行 `xattr -dr com.apple.quarantine "/Applications/Lumen Editor.app"`。
  （应用未做代码签名，属正常现象。）
- **Windows SmartScreen**：若弹出「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
- **Linux AppImage** 需要 FUSE。若报错，可 `./Lumen*.AppImage --appimage-extract` 后运行
  解出的 `AppRun`，或安装 `libfuse2`。

## 二、从源码运行（开发者）

### 环境要求

- **Node.js** ≥ 18（推荐 20/22）与 npm
- 首次安装需联网下载 Electron 运行时二进制
- **图形桌面环境**（运行 GUI 必需；纯服务器/无显示器环境见下文 FAQ）

### 步骤

```bash
# 0. 获取代码（GitHub）
git clone git@github.com:xujieyang4j/text-editor.git
cd text-editor

# 1. 安装依赖（含 Electron 二进制）
npm install

# 2. 开发模式启动（热重载）
npm run dev
```

> 已有一份被 `npm audit fix --force` 破坏的旧目录时，**不要在里面修**——换个干净目录重新
> `git clone`，避免残留的错误依赖树继续干扰。

若你所在网络下载 Electron 二进制很慢或超时，先设置国内镜像再安装：

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/   # Windows: set ELECTRON_MIRROR=...
npm install
```

若 macOS 将开发环境的 `Electron.app` 误报为恶意软件/已损坏或移到废纸篓，使用项目内置命令：

```bash
npm run dev:mac
```

该命令会自动恢复缺失的 Electron.app、仅清除当前项目运行时的隔离属性、执行临时签名并验证，
然后直接启动编辑器；不会关闭 Gatekeeper 或修改系统级安全设置。若只修复不启动，可执行
`npm run fix:mac`。正式发布的 macOS 安装包仍应使用 Developer ID 签名和 Apple 公证。

### 无需 GUI 的校验命令

在服务器/CI 上无法开窗口时，仍可校验代码正确性：

```bash
npm run typecheck   # TypeScript 类型检查（main 与 renderer 两套配置）
npm run build       # 打包 main / preload / renderer 到 out/
```

## 三、界面与基本使用

启动后界面分为三个区域：

```
┌───────────┬─────────────────────────────────┐
│  侧边栏    │  标签栏                          │
│ (文件树)   ├─────────────────────────────────┤
│           │                                  │
│           │        编辑区 (CodeMirror)        │
│           │                                  │
│           ├─────────────────────────────────┤
│           │  状态栏：行列 / 语言 / 编码 / 换行  │
└───────────┴─────────────────────────────────┘
```

- **新建文件**：`Ctrl/Cmd+N`，或菜单 File → New File。
- **打开文件**：`Ctrl/Cmd+O` 选择单个文件；文件会以新标签打开。
- **打开文件夹**：`Ctrl/Cmd+Shift+O` 载入工作区；侧边栏默认收起，按 `Ctrl/Cmd+B` 展开后，
  点击文件夹展开、点击文件打开。
- **保存**：`Ctrl/Cmd+S`。未命名文件会弹出保存对话框；`Ctrl/Cmd+Shift+S` 为另存为。
- **多标签**：顶部标签栏切换；标题前的 `●` 表示有未保存改动；点标签上的 `×` 关闭。
  关闭有改动的标签会弹确认框，避免误丢内容。
- **命令面板**：`Ctrl/Cmd+Shift+P` 打开，模糊搜索并执行任意命令（Sublime 风格）。
- **Goto Anything**：`Ctrl/Cmd+P` 模糊查找工作区文件；输入 `:` 后接行号跳转到行，输入 `@`
  后接名称跳转到当前文件的符号（函数/类/标题等）。
- **跳转到符号**：`Ctrl/Cmd+R`；**跳转到行**：`Ctrl/Cmd+G`。
- **查找/替换**：`Ctrl/Cmd+F` 打开查找面板，`Ctrl/Cmd+H` 查找并替换。
- **在文件中查找/替换**：`Ctrl/Cmd+Shift+F` / `Ctrl/Cmd+Shift+H` 打开工作区面板；支持正则、
  区分大小写、全词，以及 `**/*.ts` 等包含/排除 glob。批量替换前会再次确认，并保留文件原编码与换行符。
- **分屏与标签状态**：View → Toggle Split Editor（`Ctrl/Cmd+Alt+2`）打开第二个同步 CodeMirror 编辑器；
  每个标签会保留自己的撤销历史、选区、折叠和光标状态。
- **书签 / 宏 / 片段**：`Ctrl/Cmd+F2` 切换书签，`F2` / `Shift+F2` 跳转；Tools 菜单可录制并重放
  常用行操作宏，或通过 Insert Snippet… 插入内置/插件片段。
- **文件树操作**：右键文件/目录可新建、重命名、移到系统回收站、在文件管理器显示；外部修改的干净文件
  会自动刷新。若磁盘文件变化时本地仍有未保存编辑，顶部会提供**比较、重新加载磁盘版本、保留本地版本、
  另存为**四种冲突处理方式，绝不静默覆盖本地编辑。刷新文件树会保留已展开的目录。
- **构建与语言工具**：Tools → Build 打开构建输出；Tools → Format Document 可使用项目配置的 LSP
  或 stdin/stdout 格式化工具，并将诊断显示在编辑器 gutter。外部命令在每个应用会话首次运行前均须确认。
- **行操作**：`Alt+↑/↓` 移动行、`Shift+Alt+↑/↓` 复制行、`Ctrl/Cmd+Shift+K` 删除行、
  `Ctrl/Cmd+Shift+D` 复制行/选区、`Ctrl/Cmd+/` 切换注释，命令面板里还有「行排序」。
- **语法高亮**：默认按文件扩展名自动识别（100+ 语言）。要**手动指定**：点状态栏右下角的语言
  名，或命令面板执行「View: Set Syntax…」，在弹出列表里选择——手动选择后不再被自动识别覆盖。
- **Minimap / 缩进参考线 / 标尺**：Minimap 可用「View: Toggle Minimap」开关；缩进参考线、
  竖直标尺、行尾空白高亮由设置文件控制（见下文「设置」）。
- **Markdown 预览**：Markdown 文件按 `Ctrl/Cmd+Shift+V`（或点右上角**悬浮预览图标**、或
  「View: Toggle Markdown Preview」）在旁边打开渲染预览，随输入实时更新。判定为 Markdown 的条件：
  文件名以 `.md` 等结尾，**或**在状态栏把语法设为 Markdown（未保存文件也能预览）；渲染 HTML 经
  DOMPurify 消毒，内嵌脚本不会执行。
- **HTML 在浏览器打开**：打开 `.html` 文件时，编辑器右上角出现**悬浮浏览器图标**，点击它（或
  「View: Open in Browser」）用系统浏览器预览。已保存且未改动的文件直接打开原路径；未保存或未命名
  内容使用临时快照，不弹保存窗口、不修改源文件；脏文件的相对资源路径仍以原文件目录为基准。
- **字号缩放**：`Ctrl/Cmd+=` 放大、`Ctrl/Cmd+-` 缩小、`Ctrl/Cmd+0` 复位。
- **热退出 / 会话恢复**：即使意外退出或机器崩溃，再次打开也会自动重开上次的标签与工作区文件夹，
  并**保留未保存的编辑**（有改动的文件恢复为脏状态带 `●`，未命名草稿也保留）；边打字边防抖写盘、
  原子写入不损坏。`Ctrl/Cmd+Shift+T` 重新打开刚关闭的标签。
- **主题/换行/侧栏**：`Ctrl/Cmd+K` 切换明暗主题，`Alt+Z` 切换软换行，`Ctrl/Cmd+B` 显隐侧边栏。

### 设置（持久化）

设置以 JSON 保存在系统的 userData 目录，改动即时写入、下次启动沿用：

- **Windows**：`%APPDATA%\Lumen Editor\settings.json`
- **macOS**：`~/Library/Application Support/Lumen Editor/settings.json`
- **Linux**：`~/.config/Lumen Editor/settings.json`

可配置项（同一目录下 `session.json` 保存打开的标签与文件夹，一般无需手动编辑）：

```jsonc
{
  "fontSize": 14,                    // 字号(px)，也可用 Ctrl/Cmd +/- 调整
  "tabSize": 4,                      // Tab 宽度
  "insertSpaces": true,             // 用空格代替制表符
  "theme": "dark",                  // "dark" | "light"
  "wordWrap": false,                // 软换行
  "showMinimap": true,              // 右侧缩略图
  "showIndentGuides": true,         // 缩进参考线
  "highlightTrailingWhitespace": true, // 行尾空白高亮
  "rulers": [80, 120]               // 竖直标尺所在列(留空数组则不显示)
}
```

### 项目配置、语言工具与插件

对打开的工作区执行 **Project → Configure Project…** 可以写入根目录 `.lumen-project.json`。
常用结构如下（未知或不合法字段会被安全忽略）：

```jsonc
{
  "exclude": ["**/generated/**", "**/*.min.js"],
  "buildCommand": "npm test",
  "maxFileSizeMB": 20,               // 在用户设置 settings.json 中配置；超出时不会加载到编辑器
  "keyBindings": { "Mod+Shift+R": "build" },
  "plugins": ["team-snippets"],
  "languageTools": {
    "Python": { "command": "black -q -", "args": [] }
  },
  "languageServers": {
    "TypeScript": { "command": "typescript-language-server", "args": ["--stdio"] }
  }
}
```

Language tool 从标准输入接收当前文档：普通文本输出会当作格式化结果；也可输出
`{ "content": "...", "diagnostics": [...] }`。语言服务器遵循标准 LSP JSON-RPC，
Lumen 发送 `initialize`、`didOpen`、`textDocument/formatting` 并显示 `publishDiagnostics`。
Tools → Install Local Plugin… 可从本地目录安装声明式插件；插件目录必须含 `plugin.json`，仅能提供
命令面板 insert-text 命令和 snippets，不能执行 Node/系统代码。

应用支持单实例运行、从文件关联/命令行打开常见文本文件；文件关联在重新打包安装后生效。

## 四、自行打包安装包（开发者）

产物输出到 `release/<版本号>/`：

```bash
npm run dist          # 为当前操作系统打包
npm run dist:win      # Windows：NSIS 安装程序 + 便携版
npm run dist:mac      # macOS：.dmg + .zip
npm run dist:linux    # Linux：AppImage + .deb
```

打包目标在 `electron-builder.yml` 中配置。注意：
- **macOS 安装包必须在 macOS 上构建**（苹果工具链限制）。
- Windows / Linux 目标在多数系统上可跨平台构建（在 Linux 上打 Windows 包可能需要 Wine）。

## 五、常见问题（FAQ）

**Q：⚠️ 千万不要跑 `npm audit fix --force`！**
`npm install` 后会提示若干安全漏洞并建议 `npm audit fix --force`——**请忽略这个建议**。
这些漏洞**全部位于构建/打包工具链**（`tar`、`esbuild`、`vite`、`electron-builder` 的依赖），
只在你本地 `build` / `dist` 时用到，**不会打包进最终应用、不影响终端用户、不影响运行时安全**，
属于可接受的低风险项。而 `--force` 会把 `electron`、`vite`、`electron-vite`、`electron-builder`
强制升级到互不兼容的大版本，导致：
- 再次 `npm install` 报 `ERESOLVE` peer 依赖冲突；
- `npm run dev` 报 `SyntaxError: ... does not provide an export named 'cac'`，工具链彻底崩溃。

本项目已在 `package.json` + `package-lock.json` 中**锁定精确版本**为一套经验证兼容的组合
（electron 31.7.7 / electron-vite 2.3.0 / vite 5.4.21 / electron-builder 24.13.3 / typescript 5.9.3）。

**若已经误跑了 `--force` 把环境弄坏，如何恢复？** 两种方式任选：
```bash
# 方式 A（推荐）：从 GitHub 重新 clone 干净代码
cd .. && git clone git@github.com:xujieyang4j/text-editor.git text-editor-clean
cd text-editor-clean && npm install

# 方式 B：在原目录强制装回锁定版本
rm -rf node_modules package-lock.json
git checkout package.json package-lock.json   # 恢复锁定的版本清单
npm install
```

**Q：`npm install` 报 `EROFS: read-only file system` / npm 缓存目录只读？**
默认缓存目录不可写时，指定一个可写目录：
```bash
npm install --cache /可写路径/.npm-cache
```

**Q：安装卡在下载 Electron，或报 `ETIMEDOUT`？**
设置镜像后重装（见上文「从源码运行」）：
```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm install
```

**Q：在无显示器的 Linux 服务器上 `npm run dev` 崩溃，报 `libgbm.so.1: cannot open shared object file` 或直接 core dump？**
Electron 需要图形库和显示服务，纯服务器环境默认不具备。两种解决办法：
1. 安装依赖库与虚拟显示后再跑：
   ```bash
   sudo apt-get install -y libgbm1 libwayland-server0 xvfb   # Debian/Ubuntu
   xvfb-run -a npm run dev
   ```
2. 直接在带桌面的机器（个人电脑/带 GUI 的虚拟机）上运行。
> 普通用户在正常的 Windows / macOS / Linux 桌面系统上无需任何额外配置。

**Q：只想验证代码没问题，但机器开不了窗口？**
运行 `npm run typecheck` 和 `npm run build` 即可，二者都不需要图形界面。
